# Convention: issues and their labels

The factory takes its work from GitHub Issues and hands it back the same way.
It relies on one label vocabulary in every repo it works in.

## Labels: three axes

| Axis | Label | Meaning |
| --- | --- | --- |
| severity | `critical` | Blocks a release or a live service; drop everything |
| severity | `important` | Should be fixed before the next release |
| severity | `minor` | Polish; fix in the normal flow |
| state | `needs-triage` | Maintainer needs to evaluate this issue |
| state | `needs-info` | Waiting on the reporter for more information |
| state | `ready-for-agent` | Fully specified, ready for an agent working alone |
| state | `ready-for-human` | Requires human implementation |
| state | `wontfix` | Will not be actioned |
| category | `bug` | Something is broken |
| category | `enhancement` | New feature or improvement |

Exactly one state once triaged, at most one severity, one category. Any other
label is decoration, with two the factory reads: `security` and `risk:high`
raise a run to the high tier (method section 13). A repo may add its own
labels; it never renames these ten.

## Rules the factory follows

- It takes only issues labelled `ready-for-agent`, and only when an account
  with write access to the repo applied that label.
- It hands work back as `needs-info`, `ready-for-human` or `needs-triage`,
  removing `ready-for-agent`, with a comment saying why.
- It never sets a severity: severity is set by whoever triages, never by
  automation. The issues it files carry `needs-triage` and a category only.
- Every comment an agent posts starts with the line

  ```
  > *This was generated by AI during triage.*
  ```

- Closed issues labelled `wontfix` are findings someone already declined:
  reviewers read them before grading (method section 4).

## Ranking

The order `pick: "top"` follows: severity first, `critical`, then no
severity, then `important`, then `minor`; oldest first within each. An issue
filed by automation carries no severity, so it ranks second only to
`critical`, which is where an unreviewed issue belongs until someone looks at
it.

## Backlog and roadmap live on GitHub

The backlog is the repo's open issues; the roadmap is its open milestones.
No backlog or roadmap file in the repo's docs: it would duplicate the issues
and drift from them.

## Creating the labels

```
for l in critical important minor needs-triage needs-info ready-for-agent ready-for-human wontfix bug enhancement; do
  gh label create "$l" --force
done
```

`--force` updates a label that already exists, so the loop is safe to rerun.
